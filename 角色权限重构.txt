重构任务：从权限码转向页面配置化管理
第一步：后端数据库模型（Model）重构
提示 Cursor： “请修改 SQLAlchemy 模型。删掉 User/Role 模型中复杂的权限码字段。新建一个 Page 模型（包含 id, name, path, component）和 role_pages 关联表。确保 Role 和 Page 是多对多关系。”

目标： 让 Role 拥有一个 pages 列表。

字段建议： path（路由地址）、name（页面名称，用于菜单展示）。

第二步：后端接口 API 调整
提示 Cursor： “修改登录与用户信息的 API。当用户登录成功后，不要返回权限码数组，而是查询该角色对应的所有 Page 记录，并返回一个包含页面 path 的列表（如 ['/resource', '/graph', '/audit']）。”

新增接口： 编写一个 admin 专属接口，允许更新某个 Role 关联的 Page ID 列表，实现“勾选页面即授权”。

第三步：前端路由与侧边栏权限控制
提示 Cursor： “修改 Vue3 前端逻辑。在 Pinia/Vuex 的 User Store 中存储后端返回的页面路径列表。修改侧边栏组件（Sidebar.vue），通过 v-for 循环这个列表来生成菜单。同时，修改全局路由守卫（router.beforeEach），如果用户尝试访问不在其页面列表中的 URL，直接重定向到 403 页面。”

逻辑变化： 侧边栏不再写死，而是根据 userStore.pages 动态渲染。

第四步：管理后台“角色管理”页面开发
提示 Cursor： “在管理后台创建一个‘角色权限配置’组件。展示所有角色列表，点击某个角色时，右侧显示系统中所有可用页面的复选框。点击‘保存’时，调用后端接口更新该角色的页面权限。”
