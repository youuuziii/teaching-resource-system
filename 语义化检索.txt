================================================================
任务目标：实现基于知识图谱层级路径扩展的轻量化“语义检索”功能
方案原理：
当用户搜索某个关键词时，系统不单进行字面匹配，而是利用现有的“知识点-小节-章节”
拓扑层级，在 Neo4j 中查找同一小节（Section）或同一章节（Chapter）下的兄弟知识点，
实现检索范围的“语义泛化扩展”，最后从 MySQL 中拉取关联资源并按相关度排序输出。
================================================================

请按照以下五个步骤依次实现该功能：

### 第一步：创建后端语义检索路由 (Flask API)
1. 在后端（如 app.py）中新增一个 GET /api/resources/search_semantic 接口。
2. 接口接收查询参数：keyword（搜索关键词）和 limit（可选，默认返回20条）。
3. 确保接口做好了用户身份验证（检查 Token）并能正常获取当前用户的 user_id。

### 第二步：编写 Neo4j 拓扑路径扩展查询 (Cypher 逻辑)
在接口的处理函数中，通过 Neo4j 执行以下双层扩展检索逻辑：
1. 【直接匹配】：在 MySQL 或 Neo4j 中模糊查询与 keyword 匹配的知识点（KnowledgePoint）。
2. 【层级扩展】：以直接匹配到的知识点为起点，在 Neo4j 中执行路径推理：
   - 【同小节扩展】：查找与起点知识点属于同一个 (s:Section) 的其他所有 (k2:KnowledgePoint)。
   - 【同章节扩展】：若同小节知识点不足，扩大范围至属于同一个 (c:Chapter) 下其他小节的知识点。
3. 【数据返回】：查询最终输出一个包含：[知识点ID, 关联路径类型（DIRECT/SAME_SECTION/SAME_CHAPTER）] 的候选知识点清单。

### 第三步：从 MySQL 检索资源并执行“规则加权排序”
拿着第二步获取的候选知识点清单，去 MySQL 中执行资源匹配与打分：
1. 【资源过滤】：从 resources 表以及 resource_knowledge_points 关联表中，拉取属于上述候选知识点、且审核通过的资源。
2. 【规则加权打分】：
   - 资源直接命中用户输入的知识点（DIRECT）：基础分 +100 分。
   - 资源属于同小节扩展出的知识点（SAME_SECTION）：基础分 +50 分。
   - 资源属于同章节跨小节扩展出的知识点（SAME_CHAPTER）：基础分 +20 分。
   - 【同课程激励】：若候选资源与当前检索关键词匹配到的课程 ID 一致，额外加 15 分。
3. 【排序与去重】：根据总分由高到低降序排列，并使用 Python 的 dict 或 Pandas 对相同的 resource_id 进行去重，只保留最高得分的一条记录。

### 第四步：构建统一的 API 返回结构 (支持检索理由展示)
规范化接口返回的 JSON 数据结构，必须包含“检索理由”，以便前端展示：
返回值格式示例：
{
  "total": 2,
  "items": [
    {
      "id": 1,
      "title": "中央处理器CPU结构详解.pdf",
      "chapter_name": "第五章 中央处理器CPU",
      "score": 115,
      "search_reason": "精准匹配知识点"
    },
    {
      "id": 2,
      "title": "指令流水线中的冲突解决.txt",
      "chapter_name": "第五章 中央处理器CPU",
      "score": 50,
      "search_reason": "基于同一小节知识点[CPU结构]的关联检索"
    }
  ]
}

### 第五步：前端检索组件集成与界面渲染 (Vue3)
1. 在前端搜索结果页面（或搜索组件）中，将原有的普通搜索请求切换为调用 /api/resources/search_semantic 接口。
2. 在资源列表的卡片（ResourceCard）或列表项中，新增加一个标签或文本区域，用于展示后端返回的 `search_reason`（检索理由），增强系统的可解释性。
3. 处理空状态：若没有任何匹配或扩展结果，优雅展示“未找到相关语义资源”提示。
